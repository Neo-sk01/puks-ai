What does the "Top Stock Input" field on a receipt line mean?

ANSWEREDrelevance 0.9049.9stop: Stock generation.txt

The “Top Stock Input” field on a receipt line indicates the stock generation status for that line—i.e., whether the goods have been turned into available stock.

  • 0 = Line added to receipt but not generated in stock
  • No stock entry movement is created
  • Goods cannot be used in logistics flows
  • 1 = Line generated in stock
  • Entry movement created
  • Associated expected items consumed
  • Goods available for logistics flows (e.g., picking, sampling)

Key points:

  • The field updates from 0 to 1 when you click Generate Stock on the selected lines.
  • Only lines with Top Stock Input = 0 can be generated.
  • Once generated (value = 1), the line cannot be modified or deleted.

R5

Why is stock generation a separate step after creating receipt lines?

ANSWEREDrelevance 0.8367.9stop: Stock generation.txt

Stock generation is separate to ensure control, accuracy, and proper inventory activation:

  • Receipt lines are just preparatory records
  • They exist in REL_DAT with Stock Input flag = 0
  • No stock exists yet; no movements are created; goods can’t be used in logistics
  • Lines can still be modified or deleted without impacting history
  • Stock generation is the formal confirmation step
  • Creates stock records in STK_DAT
  • Records entry movements in MVT_DAT (audit of the receipt)
  • Consumes expected quantities if linked to a supplier order
  • Makes the storage media available for logistics flows (picking, sampling, etc.)
  • Updates the stock generation status (Top Stock Input)

Operationally, this separation lets users prepare and validate receipt details (including confirming the receiving dock on the header) before officially adding the goods to inventory and logistics processes.

  • Absolute Availability Rate
  • Scope: Entire warehouse.

  • Data fields updated after calculation: OPE_TXDP (order header), OPL_TXDP (order line).

What does the restocking calculation take into account?

ANSWEREDrelevance 0.8616.1stop: Restocking calculation method.txt

The restocking calculation takes into account:

  • Replenishment unit (e.g., pallet, box)
  • Maximum quantity allowed at the picking location
  • Replenishment threshold that triggers a refill
  • Quantity of the item already allocated in orders currently in preparation
  • Current available quantity at the picking location
  • Sampling at picking not validated and REA not validated (per the Need formula)
  • Replenishments already in progress and transfers to/from the picking location

Key formulas and logic used:

  • Need = AvailableQtyPicking – sum(PickingSamplingsNotValidated) + sum(REA_NotValidated) – ReplenishmentThreshold
  • QtyToReplenish = PicSamplQty + MaxPickingQty – PicAvailableQty – ReplQty – QtyTransfToPick – QtyTransfFromPick

Decision rules:

  • If the item is in orders in preparation and current picking quantity < max at picking, generate replenishment for: Max at picking – current at picking.
  • If not in orders in preparation: generate replenishment only if current picking quantity < threshold; otherwise, no replenishment.

Notes:

  • Adjustments can be made depending on saturation, adding threshold quantity or max picking quantity.

What are the statuses a support can have after reception, and what moves it between them?

Here are the support statuses after reception and what drives transitions between them:

Statuses

  • 01 – Support in place
  • Indicates the support is in its storage location and available for operations (e.g., picking).
  • Note: 01 can mean either “already in place” right after reception or “moved to destination” after a transfer.
  • 02 – Location to be assigned
  • The support is on the reception platform; no destination location is assigned yet.

  • Support may start as 01 (already in place) or 02 (awaiting location assignment).
  • Assigning a destination location (manually in the Storage tab or via automatic location search):
  • 02 → 03 (the support now has a planned location; movement is pending).
  • Executing the physical move to the planned location (e.g., via storage operations or by using Validate Storage in the Storage tab):
  • 03 → 01 (the support is moved; initial location is replaced by the planned location; movement is recorded in history).
  • Using Validate Storage:
  • Automatically moves selected supports to their planned location and sets status to 01, making them available for preparation.

How does automatic location search work when storing a support?

ANSWEREDrelevance 0.8517.5stop: Automatic search location.txt

Automatic location search assigns a planned storage location to each support based on predefined rules, so operators don’t have to choose locations manually.

How it works

  • Launch: From the receipt’s Storage tab, select the receipt lines (supports), then either right‑click → “Launch automatic search” or use the Location search button.

  • Zone type
  • Stock constraints
  • Item characteristics
  • Capacity limitations
  • Result on the support:
  • If a destination location is found, the planned location is set and the support status changes to 03 – “movement to be performed.”
  • If no suitable location is found (e.g., zones full or criteria unmet), the “Search completed” box remains unchecked, and the line requires manual intervention or a re‑search.

  • If automatic location search is enabled on RF:
  • The system suggests a location.
  • The operator can override the suggestion or trigger a re‑search.
  • Storage confirmation (scan support → scan location → confirm) moves the support to the planned location and changes status from 03 to 01. The movement is recorded in Speed history.

Key point

  • Automatic search accelerates and standardizes placement. Lines without a valid proposal must be handled manually (e.g., declarative assignment) or by re‑running the search.

How are DFAB and DLUO dates calculated automatically from a batch at L'Oréal?

ANSWEREDrelevance 0.85832.1stop: L’ORÉAL – Batch Decoding & Automatic DFAB,DLUO Calculation.txt

At L’Oréal, DFAB and DLUO are auto-derived from the batch (LOT) using two decoding methods. The method depends on the LOT format.

  1. If the LOT starts with “+” (Method using AYR and JJJ)
  • Year: Decode the year letter via the TRANS table (TRANS_BAS), e.g., K → 2013.
  • Day of year: Extract the JJJ (001–365/366) and convert to a calendar date (respecting leap years).
  • DFAB: The resulting calendar date.
  • DLUO: DFAB + ART_NUM1 days.

Example:

  • LOT: +K0060; ART_NUM1 = 10
  • K → 2013; 006 → 6th day of 2013 → DFAB = 06/01/2013
  • DLUO = 06/01/2013 + 10 = 16/01/2013
  1. If the LOT matches ACT_ALPHA2 and does NOT start with “+” (After ISIS; Method using BYR and AMO)
  • Year: Decode the year letter via BYR (from the TRANS table), e.g., J → 2012.
  • Month: Decode the month via AMO, e.g., 7 → July.
  • DFAB: First day of the decoded month and year.
  • DLUO: DFAB + ART_NUM1 days.

Example:

  • LOT: 2YJ700; ART_NUM1 = 10
  • J → 2012; 7 → July → DFAB = 01/07/2012
  • DLUO = 01/07/2012 + 10 = 11/07/2012
  1. Invalid or non-decodable LOT

If the LOT:

  • Does not start with “+”
  • Does not match ACT_ALPHA2
  • Or lacks required letter positions

Then it cannot be decoded:

  • DFAB: manual entry
  • DLUO: manual entry
  • DLC: always manual (unrelated to batch)

DLUO calculation rule (common)

  • Once DFAB is determined: DLUO = DFAB + ART_NUM1 (days).

Also applied in Cycle Counting

  • The same decoding logic is applied in Cycle Counting (PE884), identical to the reception logic.
