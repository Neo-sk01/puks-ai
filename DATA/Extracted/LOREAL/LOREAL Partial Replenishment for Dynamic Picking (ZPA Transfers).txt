SECTION 1 — Business Context / Functional Need
1.1 Current Situation
Within the L’Oréal project, the client manages dynamic picking locations to organize
product transfers from:
• Reserve Zone
→ To
• Advanced Preparation Zone (ZPA)
Currently, Speed allows:
✔ Transfer of full supports only during ZPA trigger.
Sensitivity: Internal

[PAGE 2]
1.2 Identified Limitation
The client needs to:
• Replenish partial supports
• Transfer only a specific quantity (not the entire pallet/support)
However:
The current ZPA transfer function automatically generates full support movements.
1.3 Required Evolution
The movements generated by the ZPA transfer function must be:
→ Converted into replenishment mission lines
This allows:
• Modification of transferred quantity
• Partial replenishment of picking locations
• Flexible stock movement
SECTION 2 — Functional Objective
Transform:
Transfer Movement → Replenishment Mission Line
So that:
• Quantity can be edited
• Partial stock transfer is allowed
• Replenishment follows standard MOD131 logic
SECTION 3 — Prerequisites / Configuration
The following setup is required:
3.1 Transfer Configuration for ZPA
The transfer to Advanced Preparation Zone must be properly configured.
Sensitivity: Internal

[PAGE 3]
3.2 Dedicated ZPA Zone
A zone must exist:
Zone Name: LO_ZPA_LOREA
This zone contains:
• All dynamic picking locations
3.3 Picking Location Configuration
All dynamic picking locations must have:
Picking Flag = 1
This ensures:
• They are recognized as picking locations
• They are eligible for replenishment
3.4 Required Module
Module:
MOD131 — Picking Replenishment
Must be activated and functional.
SECTION 4 — Technical Logic
4.1 Current Behavior (Before Change)
IF ZPA Transfer Triggered THEN
CREATE Full Support Transfer
ENDIF
Result:
• Entire pallet/support is moved
• No quantity modification possible
Sensitivity: Internal

[PAGE 4]
4.2 Expected Behavior (After Change)
IF ZPA Transfer Triggered THEN
CREATE Replenishment Mission (MOD131)
ALLOW Quantity Adjustment
ENDIF
Result:
• Replenishment mission line created
• User can modify quantity
• Partial support transfer allowed
SECTION 5 — Functional Summary (RAG-Optimized)
What problem does this solve?
Speed only transfers full supports during ZPA trigger.
What does the client need?
Partial replenishment of dynamic picking locations.
What is the solution?
Convert transfer movements into replenishment mission lines.
Which module is used?
MOD131 — Picking Replenishment.
What zone is required?
LO_ZPA_LOREA.
What configuration is mandatory?
Picking locations must have Picking = 1.
What changes technically?
Transfer movement becomes replenishment mission.
SECTION 6 — Process Overview
Sensitivity: Internal

[PAGE 5]
1. ZPA transfer condition is triggered.
2. Instead of creating full support transfer:
o System generates replenishment mission.
3. User can adjust quantity.
4. Partial stock is transferred.
5. Dynamic picking location is replenished.
