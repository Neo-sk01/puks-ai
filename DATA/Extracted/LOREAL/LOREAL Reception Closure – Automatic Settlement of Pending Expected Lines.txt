BUSINESS CONTEXT
4.1 Business Requirement
Within the L’ORÉAL activity, the client requires that:
When closing a reception,
If there are still pending expected lines (not received) linked to the current reception
DO reference,
These pending lines must be automatically settled (closed).
4.2 Why This Control Is Required
This control aims to:
Prevent reporting inconsistencies
• When a reception is closed, reception data is transmitted.
• The DO reference is closed.
• The same DO reference must NOT be receivable again in another reception.
Clean the reception backlog (expected lines portfolio)
• An expected line with the same BL reference as a closed reception can no
longer be processed by operators.
• The client would otherwise need to resend a new expected line.
4.3 Clarification Regarding DO References
Speed technically allows multiple DO references per reception.
However, for this activity:
One reception = One DO reference
Therefore:
Sensitivity: Internal

[PAGE 3]
The logic must use:
REE_NOFO = BL Reference (REA_BL)
The pending expected lines to settle must match:
• The DO reference of the reception
• The BL reference (REE_NOFO)
4.4 Radio Behavior
There will be:
No reception closure allowed from radio.
This option will be blocked.
Closure is handled only in Speed Admin.
CONFIGURATION PARAMETER
Parameter Description
ACT_TOP21 Enables or disables automatic settlement logic
If:
ACT_TOP21 = 1
→ Apply settlement logic.
If:
ACT_TOP21 = 0
→ Standard behavior (no automatic settlement).

6.2 Functional Trigger
Trigger occurs:
When:
• A reception is selected
• User clicks the "Close" button
• Reception closure is completed
Then:
→ Execute additional logic via PE22.
6.3 PE22 – Pending Line Settlement Logic
Condition
IF ACT_TOP21 = 1
Then execute the following:
Step 1 – Verify Pending Lines
After reception closure:
Check if there are remaining expected lines (attendus):
• Linked to the same DO reference
• Matching BL reference (REE_NOFO = REA_BL)
• Not fully consumed
Step 2 – Behavior
Case 1 – No Remaining Expected Lines
Sensitivity: Internal

[PAGE 5]
If no pending expected lines exist:
→ Do nothing.
Case 2 – Remaining Expected Lines Exist
If pending expected lines remain:
→ Automatically settle (close) the remaining expected lines for that reception.
6.4 Logical Flow (Pseudo-code)
IF ACT_TOP21 = 1 THEN
reception_DO = CURRENT_RECEPTION_DO
reception_BL = REE_NOFO
pending_lines = GET_EXPECTED_LINES(
DO = reception_DO,
BL = reception_BL,
status = NOT_CONSUMED
)
IF pending_lines IS NOT EMPTY THEN
FOR each line IN pending_lines:
SET line.status = CLOSED
ENDFOR
ENDIF
ENDIF

Nothing.
